CP-EY: does the idle half of the 18xD grid buy depth?  (answer: no -- and why)
================================================================================
Premise tested: the 249 circuit occupies 1576 of 4482 slots (density 0.352),
so ~65% of the grid is empty; if that emptiness is usable, depth should fall.

MEASURED (cpey_occ.py) per-wire occupancy of cpev_best.qasm (opt2, u3/cx):
  width 18 depth 249 cx 520 u3 536, occupied 1576/4482 = 0.3516
  DATA q0-11 : 859 / 2988 = 28.7%     (q3 highest at 54.2%, q7 lowest at 18.1%)
  ANC  q12-17: 717 / 1494 = 48.0%
  perfect-pack floor = 1576/18 = 87.6 layers
=> the idle slots ARE mostly on the data wires, as claimed.

CORRECTION to the cpex reading: cpex's "986 idle-but-held / 92% occupancy" is
LIVENESS (wire holds a value), not GATE TRAFFIC.  Ancillas carry gates only
48% of layers.  The two are different quantities and were conflated.
CORRECTION to the "data wires are read-only" premise: they are not.  46 of the
118 nonlinear ops already target data wires (q3 x10, q4/q5/q11 x6 each);
78 of 112 cx targets are data wires.  The banked list already writes data.

MEASURED (cpey_probe.py) the host-alphabet restriction is real:
  cpew_repair.clean_hosts() keeps only wires that are |0> at every occurrence
  (cand = {w in zeros[i]}), so wires 0-11 were excluded BY CONSTRUCTION.
  OLD alphabet: 19 keys,  32 (key,wire) pairs
  NEW alphabet: 57 keys, 843 (key,wire) pairs, 567 of them on data wires
  (38 of the 57 nonlinear wirings had NO host option at all before).
  The 4-op form G(c,w); cx(w,t); G^-1(c,w); cx(w,t) is exact for ANY initial w
  (the Margolus relative phase is diagonal in (a,b,w) and cx(w,t) does not
  touch them, so G^-1 cancels it) -- cpen_clean.py's own docstring says so.

MEASURED (cpey_sweep.py) exhaustive single host move over all 843 pairs:
  DATA hosts: n=567  best 249  median 273  mean 274.3
  ANC  hosts: n=276  best 250  median 274  mean 275.2
  moves that LOWER depth: 0.   depth-neutral: 1  ((2,11,6) -> q10, density
  0.3516 -> 0.3581, cx 520 -> 530).
=> data hosts and ancilla hosts are statistically indistinguishable.  The host
   expansion adds LATENCY (7-layer op -> ~20-layer serial chain at that point
   in the order), not merely occupancy; wire idleness cannot pay for latency
   because those slots are idle at moments when nothing is ready to run there.
   THE PREMISE IS REFUTED.

MEASURED (cpey_crit.py) where the depth actually is:
  SSA critical path, UNLIMITED wires, WAR/WAW removed : 211
  model_depth at 18 wires, all name hazards           : 243
  real transpiled depth                               : 249
=> wire scarcity is worth AT MOST 32 layers (13%) on this op list.  Every
   lever in the re-realization family (host borrowing, occupancy, data-wire
   idleness, re-scheduling) is fighting over that 32 and lands near 217.

MEASURED (cpey_floor.py) the value DAG's own floor, unlimited wires:
  57 nodes, levels [18,17,12,6,3,1], arity2 45 arity3 12, 8 phase terms
  serial xor accumulation : forward 66 -> x2 mirror = 132
  balanced xor trees      : forward 64 -> x2 mirror = 128
=> XOR re-association is worth 4 layers.  Not the lever either.
   Independently confirmed: cpet_wide.py emitted this DAG at 368 wires and
   measured DEPTH 127.  The DAG supports ~130; our realization spends 249.

BUDGET DECOMPOSITION (the useful result):
  DAG floor, unlimited wires                    132   (measured 127 wide)
  + pebbling / recomputation into 6 ancillas    +79   -> 211
  + scheduling hazards at 18 wires              +32   -> 243
  + transpile                                    +6   -> 249
The dominant term is the pebbling, and no re-scheduling of the existing op
list can recover it: the recomputation is already baked in as extra ops.

MEASURED (cpey_sched.py) the K=18/T=24 pebble schedule (cpet, CP-SAT OPTIMAL):
  peak live node values 17 (fits 18), 180 toggles over 24 steps
  peak fresh-operand wires 29 (step 24), 28 (step 1); raw reads up to 12
  operand size histogram {1:60, 2:39, 3:5, 4:11, 5:4, 6:2, 7:4, 9:1}
  60 of 126 operands are single-part (readable in place, no assembly)
  Step 1 fires 12 toggles needing 12 raw reads + 12 targets = 24 wire-roles.
=> T=24 is NOT realizable at 18 wires, matching cpet_pebble2's physical model
   (W=18, T=26/28/30 all INFEASIBLE).

THE DEPTH-PER-TOGGLE-STEP RATIO IS STABLE AND PREDICTIVE:
  banked list  T=45 steps -> depth 249   (249/45 = 5.53)
  wide emit    T=24 steps -> depth 127   (127/24 = 5.29)
So depth ~= 5.3 * T.  T=26 -> 138, T=28 -> 148, T=30 -> 159, T=32 -> 170.

THE OPEN PROBLEM, SHARPLY:
Two models bracket the truth and neither is the machine.
  (a) abstract register pebbling (cpet_pebble): K=18 -> T=24 OPTIMAL, but
      "one wire per node value" is too OPTIMISTIC about assembly -- emitting
      it needs ~41 wires at the widest step (123 total, depth 430, 15 cx/gate).
  (b) strict physical pebbling (cpet_pebble2): W=18 -> T>30, but "one wire per
      node value" is too PESSIMISTIC -- it forbids a wire from carrying an
      XOR-accumulation of several node values, which is exactly how the banked
      list fits 23 live values onto 18 wires at 4.4 cx/gate.
The unmodelled game is: a wire holds an XOR-ACCUMULATION of node values, a
toggle targets any wire, and an operand is free when some wire's current value
already equals it.  That game has never been solved or emitted.  Its answer
lies in T in [26,32] -> depth 144..170 at the banked list's cx/gate rate.

STATUS: 249 / 520 unchanged and still the shipping submission.
