STEP 0c STRUCTURAL: the span of an in-place program
  An in-place AND written onto a DATA wire never enlarges the affine span of
  the wire values: the six y wires stay a bijective re-encoding of y, hence
  six linearly independent functions, so span = 7 (with the constant) no
  matter how many gates are applied.  Only a write onto a wire that is still
  0 adds a dimension.  Hence on 8 wires the span is at most 9-dimensional.
  Consequence, measured: the record's y fold (re-index 11-v, 4 free affine
  ops, then the nibble fold, 1 AND3 + 1 AND) leaves the scorers EXACTLY
  where raw y is -- 3 code functions in the span still miss 7 difference
  vectors / 936 bad pairs, Goal(function-of-lev) residual 58 both before and
  after.  The fold reshapes the frame but adds no dimension, so it cannot by
  itself deliver a code.  (cpdo_diag.py)
  Counting bound.  With w wires, span dimension d <= w+1, and c code bits,
  the code is a linear map on the span; two inputs collide iff their state
  difference lies in the (d-c)-dimensional kernel W.  Differences live in the
  8-dimensional subspace V of vectors with the constant coordinate 0, so
  dim(W cap V) >= d-c+8-d = 8-c, and every one of its 2^(8-c)-1 nonzero
  vectors must avoid the realised difference set D.  Measured |D| = 63 of 63
  at d=7 (so 7 forced collisions), 119 of 127 at d=8.  For c=3 that demands a
  5-dimensional subspace (31 vectors) inside the 8 non-differences -- flatly
  impossible.  This is why "3 code bits that refine lev on their own" is the
  wrong target on 8 wires, and why the comparator must read h as a 7th input
  so that only (c_y,h) JOINTLY has to determine lev.

STEP 3 (comparator) -- analysis done, assembly NOT reached.
  P(c_y,c_x) = [lev-1 < cap] on the realised code pairs.
  3-bit codes, 36 care rows: degree-2 completion exists for 0 of the 225
    affine-orbit code pairs -> a pure-CZ comparator is impossible.
    A degree-3 completion exists for 22 of 225 -> a comparator made only of
    CCZ/CZ legs (no ANDs, no scratch) is available for those code pairs.
  4-bit codes, 36 care rows: 0 of 4000 random code pairs have a degree-2
    completion.  PROOF (new): on a product care set a degree-2 function is
    exactly q_y(u) + q_x(v) + B(u,v) with B bilinear, so every column of
    M[L][C] = [L<C], taken modulo the constant and one fixed function, has to
    be a LINEAR function of the code.  M's column space is {v : v_5 = 0},
    5-dimensional, and the all-ones vector lies outside it, so those columns
    span at least 5 dimensions, while the linear functions of a k-bit code
    span at most k.  Hence a pure-CZ comparator needs k >= 5 code bits on
    EACH side (11 designated registers with h) -- it is not reachable with
    the 3- or 4-bit codes that 18 registers allow.
  Corollary used above: [lev <= cap] = XOR_k ([lev=k] & [cap>=k]) would be
  five CZ legs if both sides published thermometer codes, and the bound says
  five bits per side is exactly the price of that.
  A cheap injective 3-bit code exists and is worth recording:
    c_y = (T2, T4, T1^T3^T5) with Tk = [lev <= k] gives the six levels the
    distinct words 111,110,010,011,001,000 (lev 1..6), and each Tk is a union
    of two intervals, [|y-19| <= a] u [|y-41| <= b] with a = 2,4,6,7,8 and
    b = 2,4,5,6,12.
