STEP 2 (LEVER B: linear register allocation, cpdn_emit18.py + cpdn_run18.py)
 method: register states are vectors over the base atoms {ONE, 12 data bits,
 one atom per AND}; an operand is available iff its vector is in the span of
 the current states (Gaussian solve with the target register removed, the
 null-space combinations searched for the shortest CX route).  The plan is
 generated from the netlist itself: topological build order, and as soon as
 every gate of a code bit's output set exists that whole XOR is PARKED on one
 register (a data register whose raw bit the output set contains -- then that
 register holds exactly the code value -- else a scratch), after which the
 bit's whole cone is unbuilt by repeating its ANDs.  Lifetimes obey the
 uncomputation rule: a gate must outlive the unbuild of every consumer.
 Greedy target choice + random restarts scored by cpae_core.model_depth.
 Every program below has check_block == (0, []) on LOGO before measuring.

 WHY (the erasure argument, and it is structural, not a search failure)
  1 The 12 data registers carry 12 independent input atoms.  CX is a row
    operation, so it can never reduce that rank, and an input atom cannot be
    uncomputed (that needs a second copy of itself).  A data register can
    only be REPLACED: accumulate a value v whose XOR set contains the raw bit
    d, and the register then holds exactly v.
  2 But raw d is then recoverable only from the gates in v's set, so those
    gates must stay live for as long as anything still reads raw d.  Since
    every lev bit is a function of all six y bits and every cap bit of all
    six x bits, that is "until the whole side is finished" -- so hosting is
    free only for the LAST bit of each side, and costs exactly one stranded
    scratch for every earlier one.  Parking the value in a scratch costs the
    same one register.  Measured: the host candidate list was empty at every
    park in V1/V2, which is why hosting on/off measured identically.
  3 No lev or cap bit is affine in any single variable (checked: the
    derivative D_a f is constant for no (bit, variable) pair in any of the
    orbits 0,1,2,3,9,10), so the "output set contains y_a and no gate reads
    y_a" escape does not exist.
  4 Hence at the comparator the span must contain 6 independent code values
    on top of the 12 input dimensions, i.e. 18 registers exactly, with
    nothing left for the comparator's own ANDs.  18 registers can hold the
    one-comparator form only if the comparator is a pure sum of products of
    linear forms in the code bits, and CP-DM already proved that UNSAT.
 The real gap between 18 and the 51 measured is not that argument but the
 CONE SIZE: cpdl_xi_10's three output sets reach back across the whole
 35-gate netlist, so its park cones cover nearly every gate and almost
 nothing can be unbuilt before the end.
